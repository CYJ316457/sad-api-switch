# SAD API Switch

SAD API Switch 是一个本地运行的 AI API 渠道管理与转发工具。它把多个上游模型服务统一成一个本地 API 入口，客户端只需要接入 `http://127.0.0.1:9090`，就可以通过模型名、分组或 `auto` 自动路由到可用渠道。

本仓库基于 API Switch 做了面向个人使用的增强，重点优化了渠道导入导出、模型映射、模型管理分类、一键测速和使用日志展示。

## 主要功能

- 多渠道管理：支持添加、编辑、启停多个上游 API 渠道。
- 本地统一代理：默认监听 `9090` 端口，对外提供 OpenAI 兼容入口。
- 多协议适配：支持 OpenAI、Claude、Gemini、Azure、OpenAI Responses 和自定义 OpenAI 兼容服务。
- 自动模型获取：渠道配置后可从上游拉取模型列表，并选择要加入模型池的模型。
- 模型池管理：统一管理可对外使用的模型条目、启停状态、分组、排序和测速结果。
- 自动容错：请求失败时可切换其它可用模型条目，并对异常模型做冷却或禁用处理。
- 使用日志：记录请求模型、真实上游模型、渠道、耗时、首字时间、输入输出 token、缓存 token 等信息。
- 便携运行：SQLite 数据库默认保存在程序同目录，适合本地直接运行和迁移。

## 本分支新增和修改

### 模型映射

新增“下游模型名 -> 上游真实模型 ID”的映射能力：

- 下游模型名是客户端请求时使用的模型名。
- 上游模型 ID 是实际转发给渠道服务的模型名。
- 转发请求时使用上游真实模型 ID。
- `/v1/models` 返回下游模型名，方便客户端只看到自定义模型名。
- 模型管理中显示“映射名称 <=> 真实模型 ID”。
- 模型条目右键可以快速编辑下游模型名。
- 上游模型 ID 不在快速编辑中手动修改，避免误改真实路由目标。
- 无映射模型会显示提示 icon。

### 模型管理分类

模型管理搜索框下方新增模型名前缀 tab：

- 按下游模型名的前 7 个字符分类。
- 如果没有下游模型名，则默认使用上游模型名分类。
- 切换 tab 后，列表只显示当前分类下的模型。
- 一键测速现在只测速当前选中的模型 tab 下的模型。

### 渠道导入导出

渠道管理页新增一键导入和一键导出：

- 导出为 JSON 文本文件。
- 导出时由用户选择保存位置，类似浏览器下载文件。
- 导出内容包含渠道数据和模型池映射数据。
- 导入时会恢复渠道、选中模型、模型映射、分组和启用状态。
- 兼容旧版只包含渠道的导出文件；旧文件本身没有映射数据，导入到新库时无法恢复映射。
- 导入导出不再弹多余成功提示，只保留系统文件选择/保存提示和错误提示。

### 使用日志优化

使用日志增加了缓存 token 展示：

- 后端不新增数据库列，缓存读写数据写入 `usage_logs.other` JSON。
- 支持读取常见上游返回字段，例如 `cached_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`。
- 输入 token 单元格按自适应三行展示：
  - 第一行：输入 token 数量。
  - 第二行：缓存读 token。
  - 第三行：缓存率。
- 无缓存读时只显示输入 token 数量。
- 顶部输入 token 汇总卡片显示当前已加载日志的缓存读总量和缓存率。
- 日志表格布局调整：渠道、令牌、模型、耗时列更窄，输入 token 列更宽；令牌列最多显示 5 个字符，完整值可 hover 查看。

## 快速使用

1. 启动程序后进入渠道管理。
2. 添加上游渠道，填写 API 类型、Base URL 和 API Key。
3. 点击获取模型，选择需要启用的模型。
4. 进入模型管理，按需要编辑下游模型名、分组、启停和排序。
5. 客户端配置：

```text
Base URL: http://127.0.0.1:9090
API Key: 任意值，除非你在设置里启用了访问密钥校验
Model: auto 或模型管理里显示的下游模型名
```

## 上游和下游定义

- 下游：调用 API Switch 的客户端，例如 ChatGPT 客户端、IDE 插件、命令行工具。
- 上游：API Switch 实际转发请求到的模型服务商或中转服务。

模型映射示例：

```text
下游请求模型名: coding-fast
上游真实模型 ID: gpt-5.4
```

客户端请求 `coding-fast`，API Switch 对上游实际请求 `gpt-5.4`。

## 开发运行

项目使用 Tauri v2、Rust、React、TypeScript 和 SQLite。

安装依赖：

```powershell
pnpm install
```

启动开发版：

```powershell
pnpm dev
```

只构建 Web 管理端：

```powershell
pnpm build:web-admin
```

Rust 检查：

```powershell
cd src-tauri
cargo check
```

常用测试：

```powershell
cd src-tauri
cargo test proxy::forwarder::tests
cargo test proxy::handlers::tests
```

## 项目结构

```text
src/                 前端管理界面
src/features/        渠道、模型池、日志等功能模块
src-tauri/src/       Rust 后端、代理转发、协议适配、数据库
models.json          内置模型元数据
dist-web-admin/      Web 管理端构建产物，本地生成，不建议提交
src-tauri/target/    Rust 构建产物，本地生成，不建议提交
```

## 数据存储

默认数据库文件：

```text
api-switch.db
api-switch.db-wal
api-switch.db-shm
```

它们保存在可执行文件同目录，属于本地运行数据，不应提交到仓库。

## 说明

这个仓库偏向个人本地使用场景，重点是降低多渠道、多模型和模型别名管理的操作成本。若要公开发布安装包，建议先重新整理版本号、发行说明和构建产物。
